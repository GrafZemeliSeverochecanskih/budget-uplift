| # | Decision | Reason |
|---|---|---|

| D4 | Email costs: Mens $0.10, Womens $0.08 (assumed; Hillstrom has no cost data). | Unequal costs make the arm choice a genuine multiple-choice knapsack instead of "pick the best arm". The absolute level only scales the budget axis. |
| D5 | Budget `B = fraction x n x mean email cost`, fraction in {0, 0.1, ..., 1.0}. | One interpretable axis: fraction 1.0 can email everyone at the average cost (but not everyone with the dearer Mens e-mail). |
| D6 | Objective is incremental **spend** (revenue), not profit; costs only enter the budget constraint. | As specified in TODO Sec. 3. Profit would need a margin assumption on top of the cost assumption; listed as a limitation. |
| D7 | RCT analysis (Sec. 1) uses all 64,000 rows. | Nothing is tuned there; randomisation, not the split, protects those estimates. Everything that is fit or selected (Sec. 2-5) uses train only. |
| D8 | Regression adjustment = Lin (2013) fully interacted OLS with centred covariates and HC2 SEs; covariates = all encoded features (one level per one-hot block dropped) + `log1p(history)`. | Consistent under randomisation even if the linear model is wrong; with `history` alone it is CUPED. |
| D9 | Power: two-sided two-sample z-test, equal arms, pooled SD of spend; the interval on required n maps the ATE CI endpoints. | Simple, standard, and makes the dependence on the noisy effect size explicit. |
| D10 | One LightGBM parameter set per outcome, chosen by 3-fold CV MSE of the outcome model mu(x, a) on train, shared by all base models of all learners. | Outcome-MSE tuning is the standard nuisance-tuning choice; it keeps the learner comparison about the meta-algorithm, not per-learner tuning luck. It does not directly optimise CATE. |
| D11 | Propensity fixed at 1/3 in every learner (X-learner within-pair weight 1/2; EconML DR-learner and CausalForestDML get a `KnownPropensity` classifier). | PROJECT.md: use the design propensity, do not estimate it. |
| D12 | The learner used downstream (Sec. 3-5) is chosen on a 25% arm-stratified hold-out of **train** by the sum of per-arm Qini on spend; then all learners are refit on full train for the test evaluation. | Never select on test. |
| D13 | Qini coefficient = area between the Qini curve and the random diagonal, per customer of the arm-vs-control subsample; AUUC = area under the uplift curve, plus AUUC lift over random. Bootstrap CIs resample the test rows with predictions held fixed. | The interval covers evaluation noise only, not refit noise; stated in the docstring. |

| D14 | Exact IP solver = **SCIP** through OR-Tools `pywraplp` (LP-based branch and bound, relative MIP gap 1e-6). CP-SAT is still run for n <= 10k and reported. CBC was tried and dropped. | Found while writing the unit tests, before any allocation result on Hillstrom: on a 2,000-customer synthetic instance with a non-binding budget, CP-SAT hit its 20 s limit with an objective 1.4% *below* the Lagrangian solution (which is provably optimal there: dual bound = objective). SCIP solved the same instances to optimality in < 1 s, and 64k-customer instances in 30-55 s; CBC returned no solution at 64k within 60 s. The multiple-choice knapsack has an almost integral LP relaxation, which LP-based solvers exploit and CP-SAT does not. |
| D15 | Pairs with tau-hat <= 0 (or unaffordable alone) get no IP variable. | Provably does not change the optimum; halves the model size. |
| D16 | Random targeting and "best single arm" are evaluated as **stochastic** policies: each customer is e-mailed with probability q chosen so the expected cost equals B (random arm for random targeting; the train-best arm otherwise). | Their values are then exact expectations; no Monte Carlo noise from drawing one random subset. |
| D17 | "Best single arm" = largest train difference-in-means on spend. Our policy = IP on tau-hat from the train-selected learner (D12). DR uses per-arm LightGBM outcome models fit on train. | Nothing about the policies is chosen with test data. |
| D18 | Confounding extension: primary outcome **visit**, spend reported as well; propensity = multinomial logistic regression, outcome model = per-arm OLS, Hajek-normalised IPW and AIPW; bootstrap refits both models in each resample; RCT benchmark = full-data difference in means. | In the control arm visit rises from 8.5% to 13.6% across history quintiles, while spend's gradient is noisy (D8 found covariates explain ~0.1% of spend variance). The bias created by selecting on history is therefore detectable for visit but likely buried in noise for spend. |
| D19 | Robust allocation: 50 refits of the selected learner on arm-stratified bootstrap resamples of train; allocate on the per-customer 10th percentile of tau-hat; evaluate with DR on test and report mean and 5th percentile of the test-bootstrap distribution. | As in TODO Sec. 5; 50 refits is the compute/precision trade-off for a per-customer quantile. |
| D20 | LLM features: sentence template in `llm_features.describe`, `all-MiniLM-L6-v2` embeddings, PCA(8) fit on train rows, appended to the selected learner's features with the Sec. 2 LightGBM parameters (not re-tuned). Gain reported as a paired bootstrap CI of the Qini difference. | Keeps the comparison one-variable: same learner, same parameters, +/- embedding features. |
| D21 | Optional Criteo scale check **not run**. | Both URLs in scikit-uplift 0.5.1 (`criteo-bucket.s3.eu-central-1.amazonaws.com/criteo10.csv.gz` and `criteo.csv.gz`) and the Criteo AI Lab link `go.criteo.net/criteo-research-uplift-v2.1.csv.gz` returned HTTP 404 on 2026-10-06. Finding another mirror is a scope/provenance decision left to the project owner. `criteo.enabled: false` in config. |

## 2026-10-06 - positive control, fixed before any run on it (frozen in its own commit)

| # | Decision | Reason |
|---|---|---|
| P1 | Semi-synthetic positive control: real covariates, real arm assignment, real 70/30 split; simulated `visit` and `spend` with a known effect (config `positive_control`). Womens e-mail raises purchase probability by 3 pp (+$3.00 expected spend) and visit by 10 pp **only** for `womens == 1 and recency <= 6` (32% of customers); Mens e-mail has a small uniform effect (+0.2 pp purchase = +$0.20, +3 pp visit). | Answers the question the real-data null leaves open: was there no signal, or would the pipeline have missed one? The segment rule is simple enough to state in one line and learnable by trees. |
| P2 | Realistic noise rather than an easy target: baseline purchase 0.6% (as in Hillstrom), purchase amount LogNormal with mean $100, sigma = 1 (heavy right tail), baselines vary with history (prognostic, not effect-modifying). Expected in-segment Womens effect ~ 4 standard errors on the test split. | A positive control that is trivially detectable proves little; one at the edge of detectability with the same sparsity as the real data is informative. |
| P3 | Everything downstream is the unchanged real-data code path: same LightGBM CV tuning, same train-hold-out learner selection, same IP, same OPE, same budgets, same costs. Added outputs: correlation of tau-hat with true tau (bootstrap CI over test rows), the true incremental value of every policy (mean of the true tau at the assigned arm), and an oracle policy (IP on the true tau). | Only the outcome generator differs, so the comparison isolates the data. |
| P4 | `make quick` / `run_all --quick`: 50 bootstrap reps everywhere, 10 robust refits, solver benchmark at n in {1k, 10k} with CP-SAT only at 1k; outputs to `results/quick/` and caches to `data/processed/quick/`, never overwriting the full results. | Requested for reviewers. The full benchmark at 64k alone takes ~15 min. |

## v1.1 - sweep design, fixed before any sweep code ran (frozen in its own commit, 2026-10-07)

| # | Decision | Reason |
|---|---|---|
| V1 | Heterogeneity is varied at a **fixed average** Womens effect: inside the segment mean*(1 + h(1-s)/s), outside mean*(1-h), s = segment share in the full Hillstrom covariates (0.320). h in {0, .25, .5, .75, 1}; h = 1 reproduces the v1.0 positive control. Mens keeps its uniform v1.0 effect. | Separates "how much is there to target" from "how big is the effect on average"; otherwise larger h would also mean larger ATE. |
| V2 | n in {4k, 16k, 64k, 256k} customers per replication (covariates resampled with replacement from Hillstrom; arms re-randomised with propensity 1/3; 70/30 split), 20 replications per cell. | 64k is Hillstrom's size; the grid spans 16x below to 4x above it. Resampling keeps the real covariate distribution at every n. |
| V3 | One learner (S, the v1.0 positive-control spend choice) with the v1.0 CV LightGBM parameters, not re-tuned; allocation by the Lagrangian heuristic at budget fraction 0.3; outcome = spend. | Hundreds of fits are needed; v1.0 showed the Lagrangian within 0.34% of the exact IP. Fixed parameters are a limitation at small n (min_child_samples = 400) and are stated as such. |
| V4 | Per cell, two quantities. (a) **True** gain = known incremental value of the targeted policy minus that of random targeting (and of the train-best single arm), averaged over replications, with a t-interval across replications; the heatmap marks cells whose interval excludes 0. (b) **Detection rate** = share of replications in which the practitioner's DR estimate of the paired difference has a 95% CI above 0 (influence-function SE on the test split). | (a) answers "does targeting pay off"; (b) answers "would an analyst with one experiment of size n be able to tell". The analytic SE replaces the bootstrap for speed; it is the same DR estimator as `ope.py`. |
| V5 | Gains are also reported against the **best single arm**, not only random targeting. | Random targeting splits the budget over both arms, so "beats random" includes the gain from merely choosing the better arm, even at h = 0. The single-arm comparison isolates the value of heterogeneity. |

## v1.2 - profit objective, fixed before any v1.2 code ran (frozen in its own commit, 2026-10-08)

| # | Decision | Reason |
|---|---|---|
| R1 | Profit = margin x incremental spend - e-mail cost spent; margin **0.30** (assumed), sensitivity at 0.15 and 0.50; e-mail costs unchanged ($0.10 Mens, $0.08 Womens). | Hillstrom has neither margins nor costs; 30% is a conventional apparel gross-margin-on-revenue order of magnitude. The sensitivity range shows how much the conclusion depends on it. |
| R2 | Profit-targeted policy: maximise sum(m*tau-hat - c)*x subject to the budget (Lagrangian + greedy repair on the profit scores). Compared with the v1.0 revenue-targeted policy (same tau-hat, maximise sum tau-hat*x), the best single arm, random targeting and no e-mail; positive control also gets an oracle. | The profit objective changes *who* is worth e-mailing (only m*tau > c), not just how many. Same allocator as v1.1. |
| R3 | Budget grid extended with 1.2 (more than the cost of e-mailing everyone, i.e. unconstrained). Profit-optimal budget = argmax of estimated profit over the grid; its interval = percentile interval of the argmax over 500 customer-bootstrap resamples of the repeat-averaged per-customer DR scores. | The question is "how much should we spend?", which needs an interval on the argmax, not only on the value. |
| R4 | **Cross-fitted** evaluation on all 64,000 customers: 5 folds x 10 repeats; per fold the fixed v1.0 learner (X real, S positive control) and its outcome model are fit on the other folds; DR scores on the held-out fold; repeats combined DML-style. Learners and LightGBM parameters are fixed from v1.0 (not reselected). | Uses 3.3x more evaluation data than the v1.0 test split and includes model-refit variance in the interval, which v1.0 intervals ignored (README limitation). Fixing the learner a priori keeps cross-fitting honest (no selection on evaluation folds). |
| R5 | A direct comparison of interval widths: v1.0 test-split DR CI vs v1.2 cross-fitted CI for the same revenue objective. | Shows what cross-fitting buys and costs, rather than asserting it. |

## v1.3 - direct policy learning and chance constraints, fixed before any v1.3 code ran (frozen in its own commit, 2026-10-08)

| # | Decision | Reason |
|---|---|---|
| L1 | Direct policy learning = EconML `PolicyTree` (depth 2 and 3, min 200 customers per leaf) fit to profit rewards m*Gamma - cost, with Gamma the DR pseudo-outcomes of spend; Gamma's outcome model is nested-cross-fitted (2 inner folds) within each training fold. | Policy learning maximises the DR estimate of policy value directly (Athey & Wager), instead of first estimating tau. Shallow trees are interpretable and robust when tau is noisy, which is exactly the Hillstrom situation. Nesting keeps Gamma honest on the data the tree is fit to. |
| L2 | Budget for trees: penalty lambda*cost on rewards; lambda = smallest value in {0} union 24 log-spaced values in [0.01, 20] whose training-fold spend <= B. Budgets {0.2, 0.4, 0.6, unconstrained}. | Same Lagrangian logic as the allocator; a grid keeps the number of tree fits bounded. A tree's realised spend on new customers can exceed B - reported, not hidden. |
| L3 | Comparison with estimate-then-optimise (the v1.2 profit-targeted policy, learner X real / S positive control) on the **same** folds, 5 x 5 repeated cross-fitting, DML-combined CIs, paired differences; profit at m = 0.30. | Paired, like-for-like; reuses the v1.2 evaluation that includes refit variance. |
| U1 | Chance constraint: voucher $5 paid on each purchase by a targeted customer; cost is random; policy must satisfy P(cost > B) <= 0.05 via the normal approximation on estimated purchase probabilities; compared with the mean-budget policy (E[cost] <= B). Budgets $0.02-0.08 per customer. | Turns "random uptake" into a concrete, checkable problem. The normal approximation is accurate for thousands of independent redemptions. |
| U2 | The violation probability is evaluated with the **true** purchase probabilities on the positive control (2,000 Monte Carlo draws per campaign); real Hillstrom gets only a plug-in (model-based) violation. Purchase probabilities are estimated with per-arm LightGBM on conversion (fixed v1.0 parameters), fit on training folds. | Only the positive control knows the true uptake probabilities, so only there can a violation rate be verified rather than assumed. |

## v1.4 - sequential allocation, fixed before any v1.4 code ran (frozen in its own commit, 2026-10-08)

| # | Decision | Reason |
|---|---|---|
| S1 | Environment: 64,000 customers (Hillstrom covariates resampled per replication) in 16 batches of 4,000; outcomes from the v1.1 generator at h = 1 (= v1.0 positive control) and h = 0 (same average effect, homogeneous). One total budget, 0.3 x customers x mean e-mail cost, paced evenly (remaining budget / remaining batches); unspent budget carries forward. | h = 1 is the case where learning *who* to target matters; h = 0 checks that adaptivity does not cost anything when there is nothing to learn. Even pacing is the simplest rule and is shared by every policy, so differences come from targeting, not pacing. |
| S2 | Experiment-then-target with k in {1, 2, 4} uniform-RCT batches (6-25% of customers; RCT cost counted against the budget), then one S-learner fit and profit-targeted allocation. | The standard one-shot practice (what v1.0-v1.3 assume), at three experiment sizes, since the right size is not known in advance. |
| S3 | Bandit = bootstrapped Thompson sampling: S-learner refit after every batch on a bootstrap resample of all logged data; eps = 5% of each batch gets a uniform random arm; batch 1 is random targeting within the batch budget. | Bootstrapped TS is a simple, model-agnostic way to get posterior-like exploration from the same learner used elsewhere; the eps floor keeps every arm observed in every region of covariate space. Same learner and LightGBM parameters as the other releases (fixed v1.0 values). |
| S4 | Score = known expected profit of the assignments, sum(m*tau_true - cost), per customer, summed over the campaign; also per-batch cumulative curves. 20 replications; t-intervals across replications; paired differences (same customers and outcome draws for every policy within a replication). | Scoring with the true expected profit removes outcome noise from the comparison; pairing removes covariate-resampling noise. |

## v1.5 - selection-aware chance constraint, fixed before any v1.5 code ran (frozen in its own commit, 2026-10-09)

| # | Decision | Reason |
|---|---|---|
| K1 | Scenario, budgets, eps = 0.05, voucher $5, margin 0.30, learners, folds (5 x 3 repeats) and Monte Carlo draws are exactly v1.3b's (`chance` block); v1.5 only changes how uptake p-hat enters the constraint. The v1.3 mean-budget and plug-in chance-constrained policies are recomputed on the same campaigns as comparators. | Isolates the correction; any difference to v1.3 comes from the uptake treatment, not the setting. |
| K2 | **Recalibrated (A)**: per training fold, 2 inner splits; models fit on one half, the allocator selects customers on the other half at the same budget per customer; kappa_b = (IPW purchases of the selected customers under their assigned arm, propensity 1/3) / (sum p-hat over the same pairs), pooled over both halves, per budget, floored at 1. In the campaign p-hat -> min(kappa_b p-hat, 0.99) in the profit score, expected cost and variance. | The v1.3 diagnostic showed p-hat is calibrated overall but ~10% low among selected customers. Selecting on held-out randomised customers reproduces the selection that causes the bias, and the RCT's known propensity makes the IPW numerator unbiased for their true purchases. Applying kappa to the score too keeps the objective and the constraint consistent. The floor at 1 encodes that selection can only bias cheap-looking customers downwards. |
| K3 | **Conservative (B)**: p-hat refit on 20 bootstrap resamples of the training fold; the per-customer, per-arm 90% quantile replaces p-hat in the constraint's mean and variance only. | A model-agnostic alternative that needs no calibration split; it guards against estimation noise, which is the source of the optimiser's curse, without estimating the bias directly. |
| K4 | Main outcome = true overrun probability on the positive control (Monte Carlo with the true purchase probabilities), with true profit as the price; real Hillstrom gets plug-in quantities and kappa only. Success criterion stated in advance: an overrun interval that contains or lies below 0.05. | Same verification logic as v1.3b; the criterion is fixed now so the result cannot be reframed afterwards. |
